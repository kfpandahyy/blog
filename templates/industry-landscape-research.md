# 业界调研模板 v3（对象：厂商布局 / 产品生态）

> v3 章节结构依据：AWS Database Blog 技术 how-to 系列（2025-06 实测目录）+ Anthropic 工程博客 + 云厂 architecture blog 通行结构。
> v2 → v3 主要变化：开篇加"路线图句"；逐家拆解增加统一微结构；结尾加"给不同读者的一句话"；附录承载方法细节。

## 标题 + TL;DR + 数据截止声明
- `《XX 领域全景调研：玩家 A 与 B》`。
- TL;DR 三句：格局一句 / 最反常识发现一句 / 选型建议一句。
- **数据截至 YYYY-MM** 醒目标注。Landscape 没有截止声明等于不可信。

## 开篇（两段式）
1. 需求侧变化：客户在问什么、被逼着什么（AWS 范文开头："客户一直在问我们怎么把现有系统接到 AI"）。
2. 路线图句："本文先看格局地图，再逐家拆解，最后给选型建议。"

## 一、调研口径
- 信息源构成（官方文档 / 仓库 / 博客 / 财报）+ 检索语言 + 一句话免责声明：快照不是永恒真理。

## 二、格局总览（先给地图）
- 一张分类图 / 表，全文统一分类维度（按平面、按厂商类型，选一种贯穿到底）。
- 共同方法论一句话（给读者心智模型）。

## 三、逐家拆解（同构微结构，每家严格按此五段）
1. **一句话定位**（放小节标题）。
2. **盘点**：产品线 / 能力矩阵，分类逻辑说清。
3. **解剖**：架构图 + 实现原理 + 关键设计决策。
4. **安全模型**：分层写（认证 / 授权 / 执行 / 审计）。
5. **成熟度**：GA 还是预览、定价、客户信号。
- 每家篇幅尽量相等；显著短于其他家就是在告诉读者这家不重要。

## 四、横向对比
- 多维度对比表（≤ 7 维）：架构哲学、粒度、AI 注入方式、安全抓手、托管形态、开放性、成熟度。
- 每维度给判断 + 深层原因（"做深 vs 做宽"类定性）。
- 结尾**选型决策树**：if 约束 X → 选 A；if 约束 Y → 选 B。

## 五、风险与未决问题
- 供应商锁定、路线图不确定、定价陷阱、合规缺口，至少 2 条。只唱多的调研没有第二次读者。

## 六、观察与启示
- 收敛趋势 / 分歧本质 / 给读者的启示（可借鉴 + 该警惕）。

## 七、结论：给不同读者的一句话
- 开发者现在装什么。
- 架构师评估时盯哪三个指标。
- 观望者等什么信号。

## 附录
- 完整产品清单 / 工具名索引 / 详细版本与日期表。

## 参考资料
- 一手优先，每条带日期。

---

## 写作规则（v3）
1. 开篇必有路线图句 + 数据截止声明。
2. 逐家拆解严格同构，读者可横向对照；每家小节标题 = 一句话定位。
3. 对比维度 ≤ 7，每维度必须带判断。
4. 风险独立成章，与机遇同权重。
5. 数字三要素：数值 + 来源 + 日期。
6. 例子先于描述：贴真实工具名 / 版本号 / 命令。
7. 章节标题断言式，3 分钟扫读测试。
8. 全文读完 ≤ 20 分钟；附录随便长。
