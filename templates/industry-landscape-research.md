# 业界调研模板（对象：厂商布局 / 产品生态，如 AWS 数据库 MCP、阿里云数据库 MCP）

> 用法：适用于调研"谁在做什么、做得怎么样、怎么选"的问题。核心是一家家拆清楚，再给横向对比。

## 文章标题
`《XX 领域全景调研：A 与 B》`——领域 + 主要玩家，结论在副标题或开头。

## 一、问题背景
- 这个领域为什么热？需求侧和供给侧各发生了什么变化？
- 两三家共同的方法论是什么（一句话）？

## 二、分析框架
- 2-3 句话说明拆解维度（类型 / 定位 / 场景 / 功能点 / 实现原理）。
- 一张总览图或分类表，让读者先有地图。

## 三、逐家拆解（每一家按同构小节写，方便对比）
每家内部固定五问：
1. **布局总览**：架构图，它怎么切分产品线/平面。
2. **类型盘点**：有哪些产品/MCP/Skill，按什么逻辑分类。
3. **定位与场景**：每个产品解决什么、给谁用。
4. **功能点**：工具列表 / 能力矩阵，突出差异化设计。
5. **实现原理与安全模型**：技术栈、关键机制、安全分层。

## 四、横向对比
- 多维度对比表（维度示例：架构哲学、产品粒度、AI 能力注入方式、安全抓手、托管形态、开放性）。
- 每个维度给判断，指出深层差异（"做深" vs "做宽"这类定性）。

## 五、使用场景
- 按用户角色列场景（开发 / DBA / 数据分析 / 运维）。
- 每家在各场景下的适配度可以打分。

## 六、观察与启示
- 收敛趋势：大家在往哪个共同点走。
- 分歧点：路线差异的本质原因（手里有什么资源决定走什么路）。
- 对自己产品工作的启示：可借鉴、该警惕。

## 参考资料
- 统一文末，官方文档 / 仓库 / 博客为主，注明日期。

---

## 写作规则（所有调研文章通用）
1. 参考资料只放文末，正文用"据官方文档"等字样指向。
2. 名词首次出现给全称 + 英文原名。
3. 数据、日期、版本号必须带来源。
4. 对比用表格，架构用 ASCII 图或列表，不用花哨格式。
5. 每家拆解用同一结构，读者可横向对照。
6. 全文读完控制在 20 分钟内。
