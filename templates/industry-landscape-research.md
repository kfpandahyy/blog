# 业界调研模板 v2（对象：厂商布局 / 产品生态，如 AWS 数据库 MCP、阿里云数据库 MCP）

> 适用：调研"谁在做什么、做得怎么样、我该怎么选"的问题。
> v2 变更：TL;DR + 数据截止声明 + 调研口径（方法章前置）、逐家一句话定位、失败/风险独立、对比章加选型决策树。

## 标题
`《XX 领域全景调研：主要玩家 A 与 B》`——领域 + 玩家，断言副标题。

## TL;DR + 数据截止声明（正文前）
- 3 句：格局一句话 / 最反常识的发现一句话 / 选型建议一句话。
- 必须注明：**数据截至 YYYY-MM**。Landscape 类文章没有截止声明等于不可信。

## 一、调研口径（方法说明，简短）
- 信息源类型：官方文档 / 仓库 / 博客 / 财报（各占多少）。
- 检索方式与语言（中英日）。
- 一句话免责声明：厂商能力变化快，本文是快照不是永恒真理。

## 二、问题背景
- 需求侧和供给侧各发生了什么变化，为什么这个领域现在热。
- 玩家共同的方法论一句话（给读者心智模型）。

## 三、格局总览
- 一张分类图 / 表：先给地图，再带路。
- 分类维度全文统一（按数据面 / 管理面、按厂商类型等，选一种贯穿到底）。

## 四、逐家拆解
每家同构七问（结构一致，方便横向对照）：
1. **一句话定位**（放小节标题里）。
2. 布局总览：架构图或清单。
3. 类型盘点：产品线 / MCP / Skill 分类逻辑。
4. 功能点：能力矩阵，突出差异化设计。
5. 实现原理：技术栈、关键机制。
6. 安全模型：分层写（认证 / 授权 / 执行 / 审计）。
7. 成熟度：GA 还是预览、定价、客户信号。

## 五、横向对比
- 多维度对比表（维度示例：架构哲学、粒度、AI 能力注入方式、安全抓手、托管形态、开放性、成熟度）。
- 每个维度给判断 + 深层原因（"做深 vs 做宽"这类定性）。
- 结尾给**选型决策树**：if 你的约束是 X → 选 A；if Y → 选 B。

## 六、风险与未决问题
- 供应商锁定、路线图不确定性、定价陷阱、安全合规缺口。
- 至少 2 条。业界调研只唱多不写风险，读者会自己扣分。

## 七、观察与启示
- 收敛趋势：大家往哪个共同点走。
- 分歧点：路线差异的本质（手里有什么资源决定走什么路）。
- 对读者自身工作的启示：可借鉴 / 该警惕，各至少一条。

## 参考资料
- 统一文末，一手优先，每条带日期。

---

## 写作规则（通用，v2）
1. **标题即判断**：小节标题用断言句，3 分钟扫读测试——只读标题能复述主线。
2. **倒金字塔**：每章首句给结论。
3. **数据三要素**：数值 + 来源 + 日期；全文顶部有数据截止声明。
4. **例子先于描述**：贴真实工具名 / 版本号 / 命令，不写"大概可以配置一下"。
5. 逐家拆解用同一结构，读者可横向对照。
6. 风险独立成章。只唱多的调研报告没有第二次读者。
7. 对比表格横向维度 ≤ 7。
8. 全文读完 ≤ 20 分钟；超了砍场景举例，对比表不砍。
