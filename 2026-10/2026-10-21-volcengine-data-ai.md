# 火山引擎 Data 与 AI 产品体系调研：四层架构、五线模型与一条数据产品线

> 一句话结论：火山引擎是字节跳动的云与 AI 服务平台，其体系可拆解为四层——Seed 模型基座、豆包模型家族（语言/视频/图像/音频/向量五条产品线）、火山方舟 MaaS 平台（企业调用模型的统一入口）、火山引擎云底座；Data 侧以 VeDI 数智平台为纲，覆盖数仓（ByteHouse）、数据治理（DataLeap）、湖仓（LAS）、BI（DataWind）与增长分析全链。AI 侧的打法是"超低定价换规模"（2024 年 5 月首发价即比行业低 99.3%），Data 侧的打法是"字节内部数据实践产品化"；截至 2026 年 6 月，豆包大模型日均 Token 调用量 180 万亿、火山方舟服务用户超 110 万，已是中国公有云大模型市场份额第一的 AI 云。

**TL;DR**
- 四层架构：Seed（自研基座）→ 豆包 Doubao（模型品牌）→ 火山方舟 Ark（企业级 MaaS，唯一官方 API 渠道）→ 火山引擎（算力/存储/安全底座）
- 豆包五线模型家族：语言（1.5→1.6→2.0→2.1 Pro，最新 Evolving 持续更新版）、视频（Seedance 1.0→2.0→2.5，30 秒单段直出）、图像（Seedream 5.0 Pro）、音频（Seed-Audio 1.0 + 语音识别 2.0）、向量（Doubao-embedding）
- AI 平台栈：方舟 CLI、AgentKit、HiAgent 3.0、ArkClaw 企业版 Agent 工作台、AI Trust 安全体系、VikingDB 向量库、veRL 强化学习框架、MCP 服务
- Data 产品线（VeDI）：ByteHouse 云数仓（M 计算组 5.616 元/小时起）、DataLeap 治理套件（4000 元/月起）、LAS 湖仓（15360 元/月起）、EMR（0.02 元/核/小时起）、DataWind BI、DataTester A/B 测试、增长分析+CDP+营销平台（6 万/年起）
- 关键运营数据（2026-06 官方口径）：日均 Token 调用 180 万亿（同比 10 倍+）、方舟用户 110 万+、年 Token 破万亿企业 200 家；IDC 口径豆包占中国公有云大模型市场份额 46.4%（2025-06）
- 两个值得注意的机制：模型"区间定价"（按输入长度分档，Agent 高频调用友好）+ 定期模型下线（2026-09 第九批，旧快照强制迁移至新版）

## 一、四层架构：先看清层级，再谈产品

| 层 | 名称 | 角色 |
|---|---|---|
| 模型基座 | Seed（字节 Seed 团队自研） | 所有豆包模型能力的研发底座，内部技术报告公开（如 Seedance 1.0） |
| 模型品牌 | 豆包 Doubao | 对外的模型品牌：C 端豆包 App 免费，企业端按 API 计费 |
| MaaS 平台 | 火山方舟 Ark | 企业调用豆包模型的唯一官方渠道；同时托管 DeepSeek 等第三方模型；提供推理、精调（SFT）、评测、批量推理、知识库、应用实验室 |
| 云底座 | 火山引擎 | 算力、存储、网络、安全；VeDI 数据产品线运行在底座上 |

这个架构的关键含义：**模型与云是同一个厂商的左右手**。豆包的定价策略可以不计短期云资源毛利（字节内部业务抖音/飞书的负载错峰直接摊薄推理成本），这是中立云平台学不来的成本结构。

## 二、AI 模型家族：五条产品线

**语言线**（迭代最快）：1.5（2025-03，MoE 稀疏架构，训练-推理一体设计）→ 1.6（2025-06，首创"区间定价"：按输入长度分档计价，0-32K 区间输入 0.8 元/百万 tokens）→ 2.0（2026-02，Seed 2.0 Pro/Lite/Mini/Code 四档，256K 上下文）→ 2.1 Pro（2026-06-23，聚焦 Coding/Agent/VLM，官方口径综合价格比 Claude Opus 4.6-4.8 低近 80%）→ "豆包大模型 Evolving"（持续更新版，输入 6 元/百万、输出 30 元/百万 tokens，官方定位 Coding & Agent 场景）。另有编程专线 Doubao-Seed-Code（2025-11，SWE-Bench-Verified 刷榜口径，综合成本比业界平均低 62.7%）。

**视频线**：Seedance 1.0 pro（2025-06）→ 2.0（2026-02，原生音视频联合生成）→ 2.5（2026-06-23 发布、7 月上线：30 秒单段原生视频、最多 50 个全模态素材联合生成、局部编辑；含视频输入 42 元/百万 tokens、不含 70 元/百万）。火山引擎总裁谭待的定调："视频生成是通往世界模型的关键路径"，已在具身智能、工业制造、智能驾驶落地场景仿真与数据合成。

**图像线**：Seedream 5.0 Pro（0.22 元/张，交互式精准编辑 + 可编辑分层设计图生成 + 联网检索）。

**音频线**：Seed-Audio 1.0（多角色对白、拟音特效 0 样本生成）；语音识别 2.0（录音文件 0.8 元/小时、流式 1.0 元/小时）。

**向量线**：Doubao-embedding（文本 0.7 元/百万 tokens、图像 1.8 元/百万），配套 VikingDB 向量数据库与 VikingDB 记忆库。

## 三、AI 平台与工具链（方舟之上的"应用操作系统"）

火山引擎把方舟从"模型 API 市场"扩展成了完整的企业 Agent 栈（2026-06-23 夏季 FORCE 大会集中发布）：

- **方舟 CLI**：终端/Agent 内的命令行入口（`npm i @volcengine/ark-cli`），把 API 获取、推理、训练串成工作流
- **AgentKit + HiAgent 3.0**：Agent 开发组件与企业级多 Agent 平台
- **ArkClaw**：企业版 Agent 工作台
- **AI Trust**：AI 安全产品体系；配套大模型应用防火墙、AICC 私密计算、多模态数据湖、AI Infra 套件
- **底层件**：MCP 服务、PromptPilot 提示词工具、AI 知识管理、veRL 强化学习框架（开源）

平台运营数据（2026-06）：方舟用户超 110 万（企业与个人），年 Token 调用量破万亿的企业 200 家，半年内翻倍。

## 四、Data 产品体系（VeDI 数智平台）

VeDI 是 Data 侧的纲，卖点是"字节数据驱动实践的产品化"。产品分层与定价（官方公开价，2026 年核对）：

## 五、定价策略：三个机制值得单独记录

1. **超低定价换规模**。2024-05 豆包发布时主力模型 0.0008 元/千 tokens，官方称比行业便宜 99.3%。谭待的解释是成本而非补贴：MoE 架构、分布式推理、字节内部业务负载错峰（飞书白天高峰、抖音晚间高峰）摊薄推理成本。这条成本曲线是"模型-云同体"架构的直接红利。
2. **区间定价**（1.6 首创，2025-06）。按输入长度分档计价，深度思考、多模态与基础模型统一价格，企业用量最大的 0-32K 区间综合成本约为上一代深度思考模型的三分之一。逻辑：Agent 时代每次任务消耗大量 tokens，价格不分档会扼杀 Agent 规模化。
3. **AI 统一节省计划 + 定期模型下线**。计费项分 A/B/C 类打包折扣（A 类含豆包、扣子企业版、Trae、VikingDB）；同时旧模型快照定期强制下线（2026-09-21 第九批下线 1.5 Pro 32K 与 Seed 1.6，官方指定迁移至 Seed 2.0 Lite）——前者锁定用量，后者强制升级，都是企业采购时容易忽略的条款。

## 七、优势拆解（结构性）

1. **模型与云同体的成本结构**。字节的内部负载（抖音、飞书）与外部客户负载天然错峰，推理集群利用率是独立云厂商难以复制的——这是超低定价的物理基础，不是补贴。
2. **多模态全家桶 + 单一 API 入口**。语言、视频、图像、音频、向量五线齐备，统一从方舟调用，企业做"全模态应用"不用跨厂商集成。
3. **内部实践 → 产品的转化管道**。ByteHouse 来自字节 ClickHouse 实践、LAS 来自 Hudi 批流一体实践、DataLeap 来自数据中台实践、增长三件套来自抖音增长方法论——Data 侧每个产品都有"被字节自己用过"的背书。
4. **Agent 栈的完整度**。从模型（Agent 优化的 2.1 Pro）到平台（AgentKit/HiAgent/ArkClaw）到安全（AI Trust）到应用（扣子/Trae），火山引擎是少数能把"企业级 Agent 落地"说成完整清单的厂商。
5. **定价机制创新**。区间定价直接回应 Agent 时代的高频调用成本痛点；节省计划把模型、向量库、开发工具打包折扣，提高生态内多产品共用的留存。

## 八、主打场景与非目标场景

**场景一：Agent 规模化应用**。模型按区间计价、方舟 CLI + AgentKit 工具链、ArkClaw 企业工作台，这条链是照着"Agent 从 Demo 到生产"的痛点铺的。

**场景二：多模态内容生产**。视频（Seedance 2.5）+ 图像（Seedream）+ 音频（Seed-Audio）+ 剪映/即梦生态，营销素材、短剧、电商内容的批量产线。

**场景三：字节生态内企业**。飞书、抖音渠道与火山引擎天然打通，业务系统跑在字节系内的企业迁移摩擦最小。

**场景四：数据驱动型组织的技术栈**。增长分析 + CDP + 营销自动化三件套，适合想把"抖音式增长方法"搬到自己业务的团队。

**非目标场景**：
- 多云/中立云策略的企业（模型与云绑定同一厂商，议价与迁移弹性受限）
- 模型中立需求（第三方模型虽有 DeepSeek 等，但主力与深度优化在豆包系）
- 海外为主业务（合规、区域覆盖需单独评估；Seedance 海外可用性此前受版权合规影响）
- 对模型快照稳定性要求极高的系统（定期下线机制要求跟随官方节奏升级）

## 十、判断与建议

1. 火山引擎的竞争本质不是"模型好不好"，而是**"模型-云-内部负载"三位一体的成本结构**：内部业务摊薄推理成本 → 超低定价 → 规模 → 成本进一步下降。这个飞轮只在既有海量内部负载的公司成立，字节把它用到了极致。
2. 评估豆包不能只看单价：区间定价 + 缓存命中（KVCache）计费 + 节省计划叠加后的实际成本才是 TCO；同时把"定期模型下线"写入架构设计（抽象模型层、跟随官方迁移窗口）。
3. Data 侧选型看实践匹配度：ByteHouse/LAS/DataLeap 的价值锚是"字节内部大规模用过"，如果你的数据规模和场景形态与之类似，迁移风险低；如果是中小规模，轻量替代方案（开源 + 托管）可能性价比更高。
4. 关注一个结构信号：Agent 栈（AgentKit/HiAgent/ArkClaw）+ 模型 Agent 化（2.1 Pro 的 Coding/Agent 聚焦）+ 扣子/Trae 生态，火山引擎正在把"应用层"也收进自己的计费边界（A 类节省计划已把扣子企业版、Trae 打包）。采购时按"全栈锁定"而非"单点采购"来评估风险。
