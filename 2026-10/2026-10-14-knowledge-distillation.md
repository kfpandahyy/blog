# 知识蒸馏调研：让大模型把"判断力"传给小模型

> **TL;DR**：知识蒸馏（Knowledge Distillation, KD）是用大模型（教师）的输出和中间表征监督训练小模型（学生）的压缩技术，核心手段是软目标 + 温度缩放。2025 年因 DeepSeek-R1 的推理蒸馏而再度成为主流路线——R1 生成的约 80 万条推理轨迹把 671B 模型的推理能力灌进了 1.5B~70B 的小模型，Distill-Qwen-32B 在 AIME 2024 上达 72.6%，比肩 o1-mini。读者该做的：把蒸馏理解为"能力迁移"而非"模型压缩"，选型时与剪枝、量化、LoRA 并列评估。
> **数据截至 2026-10。** 该领域 2025 年后迭代极快，具体数字以原始论文和官方仓库为准。

---

过去两年，一个反复出现的矛盾是：最强的大模型（DeepSeek-R1 671B、o1、GPT 系列）能力惊人，但绝大多数企业既买不起也部署不动。蒸馏是这个问题最务实的答案之一——不追求复刻整个大模型，而是把它关键的"判断力"迁移到一个能落地的小模型里。

本文的路线：先一句话讲清蒸馏是什么、不是什么；再拆核心机制（软目标、温度、损失函数）；然后按响应级 / 特征级 / 关系级三种知识来源逐类拆解；接着进入 LLM 时代的主线——推理链蒸馏与 DeepSeek-R1 案例；最后给选型对比、上手路径和坑。

**类比先行**：蒸馏像老师傅带徒弟。徒弟如果只看最终成品（硬标签），学到的是"照猫画虎"；真正值钱的是老师傅做题时的犹豫——"这个答案八成对，那个看着像但其实不是"（软目标里类别间的相对关系）。蒸馏传的就是这层判断。

---

## 一、定义与边界

**一句话定义**：知识蒸馏是让一个或多个大模型（教师）产生的预测分布、中间特征或结构化关系，作为额外监督信号，训练一个更小的模型（学生）逼近教师行为的技术。

最小实例——经典 KD 的损失函数（Hinton et al., 2015）：

```
L = α · T² · KL( softmax(z_t / T) ‖ softmax(z_s / T) ) + (1 − α) · CE(y, z_s)
```

其中 `z_t`、`z_s` 是教师与学生的 logits，`T` 是温度，`y` 是真实标签。学生同时向两个老师学习：真实数据（硬标签）和教师分布（软目标）。

**is / is-not 边界**：

| 维度 | 是 | 不是 |
|---|---|---|
| 目标 | 能力迁移：让小模型逼近大模型 | 不是单纯把模型变小 |
| 手段 | 教师信号作为监督（软目标/特征/关系） | 不是改架构、不是减参数本身 |
| 结果 | 学生是独立推理的新模型 | 不是教师的一部分，推理时教师缺席 |

**与相邻技术辨析**：

| 技术 | 一句话 | 与蒸馏的关系 |
|---|---|---|
| 剪枝 Pruning | 删掉不重要的权重/通道 | 蒸馏常做剪枝后模型的"复健"教练 |
| 量化 Quantization | 降低权重精度（FP32→INT8） | 与蒸馏正交，可叠加 |
| LoRA / PEFT | 低秩适配，冻结主干 | 蒸馏训全量学生；LoRA 是另一种省钱路线 |
| 数据生成 + SFT | 用大模型产数据微调小模型 | LLM 语境下的"事实蒸馏"，经典 KD 的变体 |

关键区分：在 LLM 语境里，"蒸馏"一词发生了语义漂移。经典 KD 对齐的是 logits 分布；DeepSeek-R1 的蒸馏实际是"用大模型生成的推理数据做 SFT"。两者共享目标（能力迁移），机制不同。本文两种都覆盖。

## 二、何时用，何时不用

**适用**：

1. 部署资源受限但质量要求高：端侧、边缘、低成本 API。DistilBERT 比 BERT-base 小 40%、快 60%，GLUE 保留 97% 性能——这是蒸馏的教科书收益。
2. 教师强但无法交付：671B 的教师不可能部署到客户机房，蒸馏是学生触达能力的唯一路径。
3. 教师知识难以标注：推理链（chain-of-thought）这类能力人工标注极贵，让教师生成数据是自然选择。
4. 模型集成压缩：10 个模型的 ensemble 可蒸馏成 1 个学生（Hinton 2015 的原始动机之一）。

**不适用**：

1. 教师与学生差距悬殊且数据有限：学生容量不够，软目标里的暗知识接不住，反而过拟合教师的错误。
2. 追求与教师完全对齐的场景：蒸馏是有损压缩，学生几乎必然在某些维度弱于教师；强对齐需求该走路由/级联架构。
3. 教师本身不可靠：蒸馏会放大教师的系统性偏差（偏见、幻觉），垃圾进、垃圾出，且更隐蔽。
4. 工程预算紧张且延迟要求不极端：直接调用大模型 API 常常比自建蒸馏管线便宜。蒸馏是固定成本，API 是变动成本。

**Trade-off 本质**：用一次性训练成本 + 少量精度损失，换长期推理成本数量级下降。算这笔账，答案通常很明显。

## 四、解剖：蒸馏为什么有效

### 4.1 软目标与暗知识

硬标签只告诉学生"这是猫"。教师的软目标可能是：`猫 0.72，猞猁 0.18，狗 0.05，卡车 0.01`。这串数字携带两类额外信息：

- **类间相似结构**：猫和猞猁接近、和卡车遥远——这是数据集的流形结构，硬标签里不存在。
- **教师的置信度校准**：0.72 说明这张样本难——样本难度信号本身就是知识。

Hinton 称之为 dark knowledge。温度 T 控制这层信息显形的程度：T 越大分布越平，暗知识越突出，但过大则信号淹没在噪声里。工程上 T=2~5 常见，需调。

### 4.2 损失函数的两头

回到第一节的公式。它由两个损失加权而成：

- `T² · KL(p_t ‖ p_s)`：向教师学习，T² 因子补偿温度对梯度幅度的缩放。
- `CE(y, p_s)`：向真实数据学习，防止教师偏差被无条件继承。

权重 `α` 是质量控制阀：教师可靠、数据干净时 `α` 调大；教师有噪声时调小。这个旋钮是蒸馏调参的第一现场。

### 4.3 三个关键设计决策

1. **为什么用 KL 散度而不是直接回归 logits**：概率分布对模型输出尺度不敏感，且天然兼容多峰教师（教师认为 A、B 都可能时，KL 允许学生保留两者，MSE 会逼它选边）。
2. **为什么要温度而不是直接用 softmax 输出**：原始 softmax 把头部概率压得过于尖锐，非 top-1 类的信息量在浮点精度下接近丢失；升温把暗知识"显影"。
3. **为什么 LLM 时代主流换成了数据生成式 SFT**：自回归生成的输出空间是词表×序列长度，逐 token 对齐 logits 的监督信号嘈杂且昂贵；而"让教师先想清楚再答"的推理轨迹是可筛选、可验证、可复用的资产——质量比逐 token 模仿更容易控制。

### 4.4 流程图：一次蒸馏的完整链路

```
原始数据 ──→ 教师推理（生成软标签 / 推理轨迹 / 中间特征）
    │                              │
    │                       筛选与验证（答案正确性 /
    │                       格式 / 语言一致性）
    │                              │
    ▼                              ▼
学生训练（软目标 T²·KL + 硬标签 CE 加权）
                │
                ▼
        学生独立部署（教师离线）
```

## 五、知识来源：三种模式拆解

沿用 Gou et al.（2020）的分类法，蒸馏知识有三个来源，复杂度递增。

### 5.1 响应级蒸馏（Response-based）

- **图**：`教师 logits ──T──▶ 软目标 ──KL──▶ 学生`
- **何时用**：最常见的起点。任务有明确输出分布（分类、打分、逐 token 生成），且教师输出易获取。
- **示例**：BERT 分类层蒸馏；LLM 逐 token 的 logits 蒸馏（如部分小模型训练方案）；DeepSeek-R1 事实上的输出蒸馏（整段推理轨迹作为目标序列）。
- **注意点**：只学输出会导致学生"知其然不知其所以然"，容量差距大时瓶颈明显。

### 5.2 特征级蒸馏（Feature-based）

- **图**：`教师第 k 层隐藏状态 ──投影对齐──▶ 学生第 k' 层`
- **何时用**：学生需要学教师的表征方式，而不仅是答案——检测、分割等结构化输出任务收益大。
- **示例**：FitNets（2015）首开先河；DMAE 让学生用掩蔽特征重建教师的中间表征（ImageNet 上 ViT-B 达 84.0%）；MAE-based 蒸馏允许在极度掩蔽下稳健训练。
- **注意点**：师生层数不同，需设计层对应关系与投影矩阵；中间特征维度常不一致，对齐成本要算进账。

### 5.3 关系级蒸馏（Relation-based）

- **图**：`教师对样本间/位置间的关系矩阵（注意力图、像素关系）──▶ 学生`
- **何时用**：知识的结构在"关系"里——图像分割中像素间的全局关联、样本对之间的相似度结构。
- **示例**：Attention Transfer（2017）迁移注意力图；CIRKD（CVPR 2022）迁移跨图像的全局像素关系做语义分割；关系型方法在 CIFAR 小规模模型上提升显著（综述实验：IRG 在轻量化模型上 +2.33%）。
- **注意点**：关系矩阵计算代价 O(n²)，长序列场景需采样或低秩近似。

### 5.4 训练范式：离线 / 在线 / 自蒸馏

正交于知识来源的第二个维度：

| 范式 | 机制 | 代表 | 适用判断 |
|---|---|---|---|
| 离线蒸馏 | 教师先冻结，生成信号后退场 | 经典 KD、DistilBERT、R1-Distill | 有现成强教师；最常用 |
| 在线蒸馏 | 师生同训，互相学习 | DML（互学习）、PCL | 没有强教师，多学生互纠 |
| 自蒸馏 | 模型深层的监督浅层，或自身集成 | Born Again、BEYOND | 不想引入外部教师，白拿一点提升 |

补充一个 2025 年的新范式：**Speculative KD（SKD，Google）**——学生提议 token，教师只接受"自己也会生成"的部分，被驳回处从教师分布重采样。它把监督式 KD 和在线策略 KD 统一进一个框架，用交错采样解决"训练分布 ≠ 推理分布"的老问题，在翻译、摘要、数学、指令跟随任务上全面优于前两者。

## 六、LLM 时代的主线：推理蒸馏与 DeepSeek-R1 案例

### 6.1 DeepSeek-R1 蒸馏：一次定义了行业范式的实验

事实清单（DeepSeek-AI, 2025-01）：

- 教师：DeepSeek-R1（671B 总参 / 37B 激活，GRPO 强化学习训练）。
- 数据：约 80 万条经筛选的推理轨迹（验证正确性、格式、语言一致性、可读性）。
- 学生：Qwen2.5 系（1.5B / 7B / 14B / 32B）与 Llama3 系（8B / 70B）。
- 方法：纯 SFT，不叠加 RL。
- 结果（节选）：

| 模型 | AIME 2024 | MATH-500 | LiveCodeBench | 参照 |
|---|---|---|---|---|
| R1-Distill-Qwen-7B | 55.5% | — | — | 超过 QwQ-32B-Preview |
| R1-Distill-Qwen-32B | 72.6% | 94.3% | 57.2% | 与 o1-mini 相当 |

### 6.2 为什么这个结果重要

DeepSeek-R1 论文里有一句被低估的判断：**大模型的推理模式可以被蒸馏到小模型，且效果优于直接在小模型上跑 RL**。这改变了成本结构——与其花算力在小模型上慢慢磨 RL，不如用一次教师推理生成数据，SFT 收尾。蒸馏从"压缩技术"升格为"能力分发机制"。

同时它也暴露了蒸馏的诚实边界：

- 蒸馏相对收益在中小模型上最明显；越大越接近教师自身天花板。
- 部分非推理维度（文本理解、生成流畅度）可能出现轻微回退。
- 长思维链有过拟合风险：学生可能学会"形式上沉思"，内容空洞。

### 6.3 MoE 与生成式蒸馏的新问题

- **MoE 蒸馏**（2025-02，arXiv:2502.12947）：MoE 教师的非激活专家也携带知识，传统 KD 只用激活输出会浪费。KA（多次采样专家做知识增强）与 SAR（学生感知的路由器重加权）是首批针对性方法。
- **工业落地链**：腾讯云 TI-ONE、阿里云 PAI 均已把"R1 蒸馏小模型"做成平台化流水线（部署教师 → 批量生成 → SFT → 评测）。有实测报告：Llama-3.2-3B 经 R1 数据蒸馏后，GSM8K 准确率 69% → 75%。

## 八、对比评估：蒸馏 vs 替代路线

| 维度 | 蒸馏 | 剪枝 | 量化 | LoRA | 直接训小模型 |
|---|---|---|---|---|---|
| 精度损失 | 低-中 | 中-高 | 低（8bit） | 取决于底座 | 高 |
| 训练成本 | 中（需教师前向） | 低-中 | 低 | 低 | 高 |
| 推理加速 | 结构性（小模型） | 结构性 | 常数级 | 无 | 结构性 |
| 能力上限来源 | 教师 | 原模型 | 原模型 | 底座模型 | 数据 |
| 适合场景 | 有大教师、要落地 | 已有大模型要瘦身 | 部署硬件受限 | 垂直适配 | 数据管够 |

**决策建议**：手里有强教师、目标是部署 → 蒸馏；已有模型只想省显存 → 量化；垂域适配 → LoRA；没有教师、没有标注、只有算力 → 才考虑从头训。

## 九、实践：最小上手路径

以 PyTorch 手写经典 KD 为例（训练循环核心片段，示意）：

```python
for x, y in loader:
    with torch.no_grad():
        teacher_logits = teacher(x)                    # 教师只前向，不反传
    student_logits = student(x)
    loss_hard = F.cross_entropy(student_logits, y)     # 向数据学习
    loss_soft = F.kl_div(
        F.log_softmax(student_logits / T, dim=-1),
        F.softmax(teacher_logits / T, dim=-1),
        reduction='batchmean'
    ) * T * T                                          # 向教师学习
    loss = alpha * loss_soft + (1 - alpha) * loss_hard
    loss.backward(); optimizer.step(); optimizer.zero_grad()
```

**最佳实践**：

1. 温度从 3 起步，`α` 从 0.7 起步，各扫一档再精调——这两组超参决定八成效果。
2. 教师前向离线缓存软目标，训练时直接读——教师推理通常是管线里最贵的部分。
3. 教师-学生容量差控制在"学生能接住"的范围：差距过大先蒸中间层，再蒸输出。
4. LLM 场景优先数据质量而非数量：R1 的做法是先验证正确性再入库。
5. 评测同时跑教师与学生，保留差距看板——蒸馏效果退化时第一时间知道。

## 十、失败模式与坑

1. **教师偏差被忠实继承**。教师对某类样本系统性误判，学生会放大它。发现方法：分 slice 对比师生误差分布。绕法：硬标签损失保底 + 切片评测。
2. **分布不匹配（exposure bias 的蒸馏版）**。学生训练时见的是教师/真实分布，推理时见的是自己生成的分布，错误滚雪球。SKD 这类交错采样方法为此而生。
3. **蒸馏即泄露**。把教师输出当训练数据，可能把教师训练数据里的隐私、版权内容带进学生。R1-Distill 按各底座模型（Qwen / Llama）原始许可证合规，商用前必须核对自己场景。
4. **软目标迷信**。有综述实验显示：在数据量足够大时，硬标签 + 强增广有时追平蒸馏。先确认真的需要教师信号，再投入管线成本。

---

## 十一、结论与下一步

三行收束：

1. 蒸馏的本质是**能力迁移**，软目标 + 温度只是 2015 年的第一种实现；LLM 时代的主流实现已切换为"教师生成可验证数据 + SFT"。
2. DeepSeek-R1 证明了推理模式可蒸馏且优于小模型直接 RL，这是 2025 年最重要的方法学结论之一。
3. 选型上把蒸馏与剪枝/量化/LoRA 并列算账：一次性训练成本换数量级推理成本下降，多数部署场景成立。

下一步按角色分：

- **应用开发者**：直接用 DeepSeek-R1-Distill-Qwen-7B/14B 起步，别自己蒸第一版。
- **平台/基建团队**：评估云厂商蒸馏流水线（PAI / TI-ONE），或自建"教师服务 + 数据验证 + SFT"三段管线。
- **观望者**：盯两个指标——蒸馏小模型与教师的差距是否在收窄（能力上限信号）、SKD 类统一框架是否进入主流框架（工具成熟信号）。

## 附录

**FAQ**：

- Q：蒸馏是不是只能大模型教小模型？A：不是。在线蒸馏里同尺寸模型互学（DML）；自蒸馏里模型教自己；小模型教大模型（逆向蒸馏）也有研究。
- Q：没有教师模型能蒸馏吗？A：能，走在线蒸馏/自蒸馏，收益通常弱于有强教师的方案。
- Q：蒸馏需要多少数据？A：经典 KD 用原始训练集即可；LLM 数据蒸馏以 R1 为参照是数十万到百万级轨迹，但研究一致显示质量优先于数量。
- Q：学生能超过教师吗？A：个别任务可（自蒸馏、集成蒸馏有此类报告），整体是例外不是规律。
