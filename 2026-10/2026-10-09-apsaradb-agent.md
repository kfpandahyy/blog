# 瑶池数据库 Agent 调研：阿里云的"工单+大模型"路线，与 DBAIOps 的"图谱+推理"路线对位

> 调研对象：阿里云瑶池数据库 Agent 产品家族（ApsaraDB Agent / DAS Agent / Data Agent 系列 / AIDBS）。
> 缘起：用户问"阿里云有个瑶池数据库 Agent，啥时发布的"。答案一句话——**产品家族 2025-06-10 开放日首公开，"瑶池数据库Agent"本体（ApsaraDB Agent）2025-09-24 云栖大会发布**。本篇是[DBAIOps 论文精读](./2026-10-09-dbaiops-paper.md)的竞品对位篇：同做"LLM 数据库诊断"，阿里走工单经验+大模型路线，白鳝团队走知识图谱+推理模型路线。

## 一、发布时间与产品家族澄清

先说清楚名字，因为阿里自己的命名容易混。用户问的"瑶池数据库Agent"在官方文档里叫 **ApsaraDB Agent**，但它不是一个产品，是一个家族的四代：

| 产品 | 发布时间 | 干什么 |
|---|---|---|
| Data Agent 系列（for Analytics / for Meta）+ DAS Agent | 2025-06-10 瑶池 Data+AI 开放日首公开 | 数据分析智能体 / 元数据治理智能体 / 运维智能体 |
| Data Agent for Meta 正式 GA | 2025-07-04 | 企业数据资产盘点与自然语言管理 |
| **ApsaraDB Agent（瑶池数据库Agent）** | **2025-09-24 云栖大会**，李飞飞主题演讲发布 | 控制台智能顾问：全产品知识问答 + 实例诊断 |
| AIDBS + Agent Context | 2026-05-20 阿里云峰会首发 AIDBS；Agent Context 2026-09 云栖发布 | "AI 原生数据库服务"总平台 / Agent 上下文与记忆底座 |

配套动作：同期发布 DMS MCP Server（开源，40+ 数据源统一数据访问）、DTS One Channel For AI（向量化数据准备通道）。2026-09 云栖披露：**超 1000 家企业客户**在使用瑶池 Agent 系列产品。

## 二、ApsaraDB Agent：控制台里的"全科专家"

官方定位：7×24 云数据库智能顾问，覆盖实例全生命周期——选型、上云迁移、产品管理、运维、计费。

- **知识问答**：基于官方文档+知识库回答全产品问题，宣称自助解决 90% 以上产品咨询；还能化身"数字人"给阿里云云小二做在线辅助；
- **实例诊断**：分析指标与日志定位根因——**当前仅支持 PolarDB 和 Tair**（自家引擎优先，深度优先于广度）；
- **开源 MCP Server**（github.com/aliyun/alibabacloud-yaochi-db-mcp-server）：让 Cursor/Claude/Qoder 等 AI 编程助手直接建实例、建表、执行 SQL、调诊断。支持 RDS MySQL、PolarDB MySQL、MongoDB、Tair；用环境变量 `YAOCHI_ENABLE_WRITE_SQL` / `YAOCHI_ENABLE_DDL_SQL` 控制写权限（默认禁 DDL），带临时账号模式。

这个产品的本质是"产品咨询 + 轻诊断"入口，对标的是云控制台体验，不是 DBAIOps 的诊断深度。

## 三、DAS Agent：真正的运维大脑，DBAIOps 的直接竞品

家族里和 DBAIOps 正面交锋的是 **DAS Agent**（数据库自治服务 DAS 的大模型升级）。

- **经验底座**：阿里云 10 万+ 工单 + 专家经验（注意口径：是工单数据喂养，**不是知识图谱**）；
- **覆盖引擎**：MySQL（RDS/PolarDB/他云/自建）、PostgreSQL、Redis（Tair）、MongoDB、SQL Server、PolarDB-X——云 + 自建 + 他云统一纳管（自建/他云靠轻量采集端）；
- **能力清单**：知识问答（覆盖 OLTP 及 NoSQL，含异常处理建议/升降配/变更影响分析）、异常诊断（CPU/内存/会话实时诊断、锁分析、Tair 时延洞察与大 Key、慢 SQL、SQL 优化含上线前预检、安全风险检测）、跨引擎统一运维日报；异常检测与预警标注"未支持"（在路上）；
- **运行数字**（官方宣传口径，2025-11）：半年 10 万+ 次 AI 诊断请求；阿里云工单团队实测诊断正确率 83%（对照"当前基模准确度普遍 40%-60%"），剩余 17% 复杂问题交专家——人机协同分层；运维日报每日不低于 2 亿 token 分析规模；
- **执行边界**：明确**不自动执行**，建议需人工采纳——和 DBAIOps 一样"诊断到建议为止"，自动闭环两家都没开；
- **商业化**：按账号/推理资源预付费；是唯一入选阿里云官方 Skill 市场的数据库运维技能，可下载部署到本地 Agent；
- **合规架构**：数据不用于模型训练、审计日志本地存储不跨境、诊断中间数据即时销毁、SOC 认证；按国家/地区开通（海外模型调用路由新加坡/美国百炼）。

## 四、2026 新一代：从"Agent 产品"到"为 Agent 重做数据库"

2026 年的叙事升了一级——服务对象从人变成 Agent：

- **AIDBS**（AI 原生数据库服务，2026-05-20 首发）：企业级 Data-Centric Agent 一站式平台，五大模块：Agent 数据网关、AI 资产与企业知识服务、AI 数据准备、企业级数据库 Agent 开发平台、Data Agent 产品系列；
- **Agent Context**（2026-09 云栖）：企业级上下文数据库服务，让 Agent 的经验与进度变成"组织可复用、可管理、可治理的上下文资产"——记忆沉淀、晋升、演化；
- **PolarDB Agentic-Native**：声称承接 Agent 全生命周期四大数据域（记忆、原始语料、领域知识、业务数据）；ApsaraLakebase 主打"一份拷贝、多模统一、百万级 Agent 工作空间、3.6 秒建分支"。

这套叙事与腾讯云数据库的"Agent Memory"（开源，一周 4000+ stars）、TDSQL Nexa 正面撞上——"数据库厂商给 Agent 当记忆底座"已成国内云厂商的公开战场。

## 五、路线对位：工单+大模型 vs 图谱+推理

把 DBAIOps 和 DAS Agent 并排放，是理解这个赛道的最好切片：

| 维度 | DBAIOps（佰晟智算/上交） | 阿里云 DAS Agent |
|---|---|---|
| 经验表示 | 显式知识图谱（6 类顶点 5 类边、30 万+ 边、可消融验证） | 工单+专家文档，RAG 式知识库（无图谱叙事） |
| 数据资产 | 10 年 5,000 库 2,000 故障案例 | 10 万+ 工单 |
| 模型 | DeepSeek-R1 推理模型，图谱喂料（43.5k token prompt） | 百炼大模型（海外路由新/美） |
| 验证方式 | 论文：558 场景自建评测集 + 四指标 + HEval 人工评估 | 宣传：83% 正确率（工单场景，无公开评测集） |
| 覆盖引擎 | 4 库实测（Oracle/MySQL/PG/达梦），25 种采集 | 6 大引擎实测 + 多云自建纳管 |
| 部署 | 私有化（企业内网，医疗案例） | 云托管（按国家/地区开通） |
| 自动执行 | 无（建议人工采纳） | 无（建议人工采纳） |

判断：

1. **数据壁垒决定路线**。工单数据只在云厂商手里，创业公司拿不到，所以白鳝走图谱——把 2000 个故障案例结构化做成可推理的资产，这是小数据方的理性选择。两条路线不是谁对谁错，是资产禀赋不同。
2. **可验证性是 DBAIOps 的差异化武器**。83% 对 0.92-0.94 不能直接比（任务分布和 ground truth 都不同），但阿里口径没有公开评测集、没有消融、没有第三方复核——论文型产品的评测纪律在 to-B 宣传战里是稀缺品。反过来说，DBAIOps 没有 10 万工单的规模，也没有 1000 家客户的分发。
3. **执行闭环是全行业空白**。两家都停在"建议人工采纳"——不是技术不能，是责任不敢。谁先解决"自动变更的授权与回滚边界"，谁开第二增长曲线。
4. **命名是阿里这个家族的真实债务**。瑶池数据库Agent / ApsaraDB Agent / Data Agent / DAS Agent / AIDBS / Agent Context 六个名字四层产品线，营销发布密集但架构图要靠读者自己拼——做产品的人从这里看到的是反面教材。

## 六、批判性解读

1. **数字全是宣传口径**：83% 正确率、90% 自助解决、1000+ 客户、2 亿 token/日——均无第三方验证、无任务分布披露、无失败案例分析。引用时按"厂商宣称"处理。
2. **诊断深度存疑**：ApsaraDB Agent 实例诊断只支持 PolarDB + Tair；DAS Agent 的正确率场景是工单团队（相对标准化的问答），不等于复杂生产故障的根因定位。DBAIOps 论文那种跨库、多根因、证据链报告的评测强度，没有公开对应物。
3. **地域合规切碎**：按国家/地区开通、海外仅新/美两点路由——全球企业拿到的是碎片体验。这是数据主权时代的必然成本，但也是竞品（私有化部署）的缝隙市场。
4. **"为 Agent 重做数据库"叙事跑在产品前面**：Agent Context 的"记忆沉淀、晋升、演化"目前只有概念页和大会口径，无公开技术细节、无评测。2026-09 的"1000+ 客户"指的主要是 Data Agent 系列，不是 Agent Context。
5. **与腾讯对撞说明赛道真实**：腾讯 TencentDB Agent Memory 开源一周 4000+ stars、云厂三家全部押注——"给 Agent 做记忆/上下文底座"已从概念进入厂商军备竞赛，2027 年会出标准化协议（目前各说各话）。

## 七、对产品建设者的启示

- **评测集是护城河**：阿里有工单但不敢公开评测；你有小数据集但可以把评测做公开做扎实——在 LLM 运维这个信任敏感场景，可验证性比规模更能赢专业客户；
- **产品家族命名趁早收敛**：一个家族一个动词+一个名词，别让市场替你猜；
- **"人工采纳"是功能不是妥协**：把采纳/回滚/审计做成产品特性（谁批的、依据是什么、回滚到哪），比直接上自动执行更符合当前客户风险偏好；
- **多云纳管是云厂商的必答题**：DAS Agent 对自建/他云靠采集端纳管——"管理别人家数据库"正在成为云数据库工具的标配姿势。
