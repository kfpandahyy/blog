CPU、GPU、TPU、NPU：四类处理器的架构、定位与选型

2026-10-23 · 技术调研 · 数据截至 2026 年 10 月
先说清一个术语问题。常见的处理器分类里没有"NPG"这个类别。它能指的两个东西——实时调度领域的 Non-Preemptive Gang（一种任务调度模型）和小鹏汽车的智驾功能（Navigation Guided Pilot）——都不是芯片。按语境推断，这里要比较的应该是 NPU（Neural Processing Unit，神经处理单元）。本文按 CPU / GPU / TPU / NPU 四类展开。如果你确实指的是别的，告诉我，我再改。

这四类处理器不是四个并列的"产品"，而是一条光谱上的四个点：通用性逐级递减，对特定负载的效率逐级递增。CPU 什么都能做；GPU 把"并行"做到了极致；TPU 把矩阵乘法这一件事做成了专用机；NPU 则把神经网络推理压进了手机的几瓦功耗里。理解它们，本质上是理解一个交换：你用灵活性，换效率。

CPU：通用计算的底座

定位：一切计算的默认选项，也是其他三类处理器离不开的协作者。

CPU 的架构哲学是"把一件事尽快做对"。大容量缓存、分支预测、乱序执行、乱序提交——所有机制都服务于一个目标：让单个线程的每一步都尽可能快。它核数不多（服务器级数十核），但每个核都极其聪明。

擅长操作系统、数据库事务、控制流密集的逻辑、低延迟单线程任务、不规则的数据结构遍历。
不擅长大规模同构并行计算。让一个 CPU 跑矩阵乘法，就像让一位教授算一万道九九乘法表——他每道都对，但算不完。

AI 时代的 CPU 没有退场，而是换了角色：在 GPU/TPU 集群里，CPU 负责数据加载、预处理、调度、通信和 checkpoint；在端侧，CPU 是 NPU 的搭档，处理控制流和不适合下沉到 NPU 的算子。Intel 的 AMX、ARM 的 SME 等指令扩展也在把矩阵运算能力塞进 CPU，但对大规模 DNN 而言，它仍是辅助而非主力。

代表产品：Intel Xeon 6、AMD EPYC Turin、ARM Cortex / Oryon（骁龙 8 Elite 的 CPU 部分主频已达 4.6GHz 级）。

GPU：并行的王者，训练的主力

定位：把成千上万个简单核心组织起来，用吞吐换延迟，是深度学习训练事实上的标准硬件。

GPU 为图形渲染而生——渲染的本质是对数百万像素做同一种运算，天然并行。这个架构意外地对神经网络高度友好：矩阵乘法同样可以拆成海量独立的小块运算。NVIDIA 的 Tensor Core 进一步在 SM 内加入矩阵乘加单元，把"AI 算力"做成了与 CUDA 核心并列的硬件资源。

峰值算力分 dense 与 sparse 两种口径，不同来源差异可达一倍，横向对比时必须先对齐口径。

结构性优势：

  • 生态护城河：CUDA 是 GPU 最深的壁垒。几乎所有 AI 框架、算子库、优化工具第一时间支持 CUDA。竞争者（ROCm、oneAPI）追赶多年，生态厚度仍有代差。
  • 灵活性：精度支持最全（FP64 到 FP4），训练、推理、科学计算、图形渲染一卡多用。
  • 可获得性：自由采购、多云可得、可本地部署——这是它对 TPU 的结构性优势。

代价：功耗高（单卡 700W 至 1200W），采购成本高（旗舰卡单价数万美元），且旗舰型号受出口管制影响在部分市场不可用（如中国市场特供的 H20 性能大幅阉割）。

TPU：Google 的专用张量机

定位：为大规模矩阵运算从零设计的 ASIC，只存在于 Google Cloud，是 Google 全栈控制（芯片 + 模型 + 云）战略的核心。

TPU 的架构心脏是脉动阵列（Systolic Array）：数据在由乘加单元（MAC）组成的网格中以波浪方式流动，权重和激活值从两侧流入，中间结果在网格中传递，不必反复读写内存。这种设计把矩阵乘法的能耗大头——数据搬运——压到了最低。

核心计算单元叫 MXU（Matrix Multiply Unit），每代规模翻倍。v1 只有 1 个 256×256 阵列（且仅 INT8），到 v7 Ironwood 已是 8 个 256×256 阵列，每周期 100 万次以上乘加。

结构性优势：

  • 能效比：脉动阵列 + 专用数据通路，大规模负载下每瓦性能显著优于 GPU。有分析指出，在十万颗加速器规模上，TPU 方案四年总成本可比 NVIDIA GB200 方案节省最高 80%——注意这是分析口径，非独立验证结论。
  • 超大规模协同：Ironwood 单 Pod 9216 芯片通过 ICI 光交换组成一个逻辑整体，适合超大规模训练和推理。
  • 成本（云租用）：v5p 按需约 $4.20/芯片·小时（具体以 GCP 定价页为准），大规模长约可谈。Ironwood 无公开目录价，SemiAnalysis 估算 Anthropic 实际支付约 $1.60/小时。

代价与边界：

  • 不可拥有：只租不卖，只存在于 Google Cloud。这是硬约束，不是缺点。
  • 生态窄：JAX 是首选，PyTorch 需经 XLA 路径（TorchTPU 尚在 preview）。自定义 CUDA 内核无法迁移。任何依赖最新算子创新的研究型工作负载都会在这里受阻。
  • 灵活性低：为张量运算优化，不适合图形、通用 HPC 或非标准架构探索。
  • 可用区限制：不是每个 GCP 区域都有 TPU 配额。

谁在用：Anthropic 公开承诺接入最高 100 万颗 TPU v7（迄今最大规模的非 NVIDIA 算力承诺）；Apple、Character.AI、Hugging Face 企业版等也在 Google Cloud 上使用 TPU。Google 内部约六成 TPU v7 容量供搜索排序、Gemini 服务和 YouTube 推荐自用。

NPU：把 AI 压进几瓦功耗里

定位：端侧专用推理芯片，存在于手机、PC、汽车、IoT 设备中，不单独出售。它的核心指标不是峰值算力，而是每瓦性能和"始终在线"。

NPU 的设计哲学与 TPU 同源——专用数据通路、近存储计算、低精度优先——但目标域完全不同：TPU 优化的是数据中心级别的吞吐，NPU 优化的是 3 至 5 瓦功耗预算下的实时响应。它不做训练，只做推理。

TOPS 为 INT8 精度口径，与数据中心 GPU 的 FP8 FLOPS 不可直接换算。端侧实测数据为工程估算口径，随模型与量化方案差异较大。

结构性优势：

  • 能效数量级领先：每瓦 50-200 TOPS，比数据中心 GPU 高 1-2 个数量级。一部手机可以全天候跑人脸识别、语音唤醒、计算摄影，而电池只掉几个百分点。
  • 隐私：数据不出设备，无网络传输风险。
  • 延迟：端侧推理响应为个位数毫秒级，不依赖网络。

边界：

  • 不做训练。这是设计决定，不是暂时限制。
  • 算力天花板低：无法承担 7B 以上参数模型的高质量推理（旗舰设备跑 7B 已是内存极限）。
  • 碎片化：苹果的 Core ML、高通的 QNN、联发科的 NeuroPilot 各自为战，跨平台部署成本高。

怎么选

没有"最好的处理器"，只有"与负载匹配的处理器"。决策路径：

  1. 端侧实时 AI（手机、IoT、汽车感知）：只能选 NPU。这不是选择题，NPU 随设备而来，问题只是用不用。
  2. 大规模训练 / 高吞吐云端推理，且在 Google Cloud 生态内：TPU 值得认真评估，特别是 JAX 技术栈、稳定模型服务、成本敏感型超大规模推理。注意硬约束：不可本地部署、算子生态窄、自定义内核不可迁移。
  3. 需要最大灵活性 / 本地部署 / 最新算子 / 多云：GPU 是唯一现实选项。研究型工作负载、快速迭代、非 Google 生态，都应默认 GPU。
  4. 控制流、调度、数据预处理、小规模逻辑：CPU。它不做主角，但每台机器里都有它，所有加速器都依赖它喂数据。

现实的系统几乎总是混合架构：手机是 CPU + GPU + NPU 的异构 SoC；数据中心训练集群是 CPU 调度 + GPU/TPU 计算；Agent 时代的推理基础设施正在向"CPU 编排 + 加速器推理 + NPU 端侧预处理"的三层结构演进。选型的单位不是芯片，而是工作负载。
