# AI 相关概念全景梳理：一张四层地图看懂术语丛林

> 一句话结论：AI 概念可以用"模型层 → 使用层 → 智能体层 → 产品与商业层"四层框架装下；术语混乱的根源，大多是同一词语在不同层之间被混用（"模型会说"和"系统会做"被当成一回事）。本文给出分层地图 + 高频术语对辨析 + 一页速查，目标是看完能对任意一个 AI 新词快速定位它在哪一层、解决什么问题。

---

## 一、总图：四层框架

| 层 | 核心问题 | 代表性概念 |
|---|---|---|
| 模型层 | 大脑本身是什么、怎么来的 | 深度学习、Transformer、预训练、微调、蒸馏、推理模型、多模态 |
| 使用层 | 怎么把大脑的能力调用出来 | Prompt、Token、采样参数、Function Calling、Embedding |
| 智能体层 | 怎么让大脑连续做事 | Agent、Agent Loop、工具协议（MCP）、记忆、RAG、多智能体、沙箱 |
| 产品与商业层 | 怎么变成产品和生意 | Copilot vs Agent、计费模式、评测、安全治理、可观测 |

记住一个判别口诀：**模型层回答"会不会"，使用层回答"怎么问"，智能体层回答"怎么干活"，产品层回答"值不值钱"**。

---

## 二、模型层：模型是什么、怎么来的

### 基础谱系

- **AI（人工智能）**：总称，目标是让机器表现出智能行为。
- **ML（机器学习）**：AI 的子集，从数据中学规律，而不是手写规则。
- **DL（深度学习）**：ML 的子集，用多层神经网络学特征；今天的大模型全部属于这一类。
- **神经网络**：受神经元启发的函数逼近器，由"层"堆叠；**参数（权重）**是训练出来的数字，参数规模（7B/70B/671B，B=十亿）大致对应容量。

### Transformer 与大模型

- **Transformer（2017）**：当今几乎所有大模型的底座架构，核心是**注意力机制**——让模型决定输入中哪些词该互相"看"。
- **LLM（大语言模型）**：在海量文本上预训练的 Transformer，能理解和生成语言；是当前 AI 应用的主要引擎。
- **基础模型（Foundation Model）**：比 LLM 更宽的概念，还包括图像、语音、视频模型。
- **预训练（Pre-training）**：用无标注数据练出"通识"的过程，成本高（千卡级 GPU 月）。
- **多模态模型**：一个模型同时处理文本、图像、音频、视频；视觉理解、语音交互都靠它。
- **稠密 vs MoE**：稠密模型每次推理激活全部参数；MoE（混合专家）每次只激活一部分，用 1.6T 总参数做到近似激活几百 B 的效果——2026 年旗舰开源模型（DeepSeek、Kimi 等）的主流路线。
- **开源权重 vs 闭源**：权重开放可自部署（Llama、DeepSeek、Qwen、Kimi 开源系）vs 只给 API（GPT、Claude 系）。选型本质是成本、隐私、能力更新的三角。

### 训练相关术语

- **SFT（监督微调）**：用"问答对"教模型按格式回答。
- **RLHF / RLAIF**：用人类偏好或 AI 偏好反馈做强化学习，提升回答质量和服从度；RLAIF 用 AI 代替人打分，成本更低。
- **DPO**：RLHF 的简化替代，直接对比好/坏回答调参数。
- **蒸馏（Distillation）**：大模型当老师、小模型当学生，把"判断力"压缩到小模型——端侧、低成本场景的钥匙。
- **推理模型（Reasoning Model）**：输出前先显式推理（思维链），数学/代码能力显著更强（o1/R1/K 系列等），代价是更慢、更贵。
- **Benchmark**：能力考卷（MMLU、SWE-bench 等）；看分数要分清"知识类"和"任务类"，后者更接近真实可用性。
- **幻觉（Hallucination）**：模型一本正经地编造。根因是"预测下一个词"的目标不保证事实正确，缓解靠检索（RAG）、靠工具验证、靠推理自检，**目前没有根除手段**。
- **指令遵循 / 上下文窗口**：听不听话、一次能"看"多少输入；上下文窗口是 Agent 时代最硬的资源约束。

## 三、使用层：怎么把能力调出来

- **Token**：模型处理文本的最小单位（约 0.5-1 个汉字或 0.75 个英文单词）；**一切计费、限速、窗口长度都以 token 计**。
- **Prompt（提示词）**：给模型的输入；**System Prompt** 是开发者设定的"角色说明书"，**User Prompt** 是用户问题；few-shot（给几个示例）能显著提升格式稳定性。
- **Prompt Engineering**：通过措辞、结构、示例引导输出；不会消失，但重心从"哄模型"转向"给上下文"。
- **采样参数**：Temperature（随机性）、Top-p（截断范围）；生产环境默认低温，创意场景才调高。
- **Function Calling / Tool Use**：模型输出结构化调用请求（函数名+参数）而不是最终答案，由外部代码执行后把结果喂回——这是模型从"会说"到"会做"的第一步，也是 Agent 的地基。
- **结构化输出**：强制模型按 JSON/Schema 回答，是可编程集成的前提。
- **Embedding（向量嵌入）**：把文本/图片映射成高维向量，语义相近则距离近；是语义搜索和 RAG 的基础。Embedding 模型与生成模型是两类不同模型，别混。
- **Reranker（重排模型）**：对初召回的候选重新打分排序，检索质量的关键二段。

## 四、智能体层：让模型连续做事（AI 应用的主战场）

### Agent 本体

- **Agent（智能体）**：LLM 处于循环中，自主决定"下一步干什么"，直到目标完成。最小配方 = **Agent Loop**（推理→行动→观察→再推理的循环）+ 工具 + 记忆。
- **Harness（脚手架/线束）**：包住模型那层工程系统——循环控制、工具注册、上下文管理、权限、报错恢复；**同一模型，不同 Harness，表现天差地别**。行业共识：模型是发动机，Harness 是整车。
- **Skill（技能）**：打包好的"程序性知识"（怎么做某类事的说明书+脚本），让 Agent 即插即用新能力。
- **子 Agent / 多智能体**：主 Agent 分派任务给子 Agent；协作模式有编排者-工人、辩论式、角色分工。**注意**：多 Agent 不是默认更优，通信开销和错误放大是常见坑，先榨干单 Agent。
- **Planning / Reflection**：事前拆解任务、事后自我检查，提升长任务成功率，同样增加 token 消耗。

### 工具与协议

- **MCP（Model Context Protocol）**：Anthropic 2024-11 开源的协议，用统一方式把数据源/工具接给模型，相当于"AI 世界的 USB-C"；与 Function Calling 的关系：Function Calling 是单次调用能力，MCP 是发现和管理工具集的标准协议。
- **工具调用安全**：工具即权限，每个工具都是一次注入面，需要最小授权与审批。

### 记忆与检索

- **RAG（检索增强生成）**：先检索、再让模型基于检索内容回答——治幻觉的第一手段，也是企业私有数据接入的标准做法。链路：文档切分（Chunking）→ Embedding 入库 → 向量/全文/混合检索 → 重排 → 塞进上下文。
- **向量数据库**：存 Embedding 并做近邻检索（HNSW 等索引）；传统关系库（PG、MySQL 系）也在内建向量能力，"独立向量库 vs 数据库加向量"是 2026 年的活跃争论。
- **混合检索**：向量（语义）+ 全文（关键词）+ 标量过滤多路召回，中文场景几乎必选（词对不上时全文失效，语义模糊时向量失效）。
- **长期记忆**：跨会话记住用户/任务状态；实现三路线——RAG 式（可检索文档）、结构化（记忆数据库/知识图谱）、总结式（滚动摘要）。
- **Context Rot（上下文腐烂）**：塞进去的上下文越多，模型对中间部分注意力越差——长上下文不是无限内存，**信息管理比窗口大小更重要**。

### 运行底座

- **沙箱（Sandbox）**：给 Agent 的代码/命令执行环境做隔离与资源限额，是生产部署的生死线。
- **可观测性（Tracing）**：记录每一次循环、调用、token 消耗，Agent 排障的基础设施（Langfuse、LangSmith 等）。
- **评测（Eval）**：离线基准 + 在线抽检；Agent 的"坏了怎么查"比"跑起来"更耗工程。
- **Prompt Injection**：攻击者通过输入内容劫持 Agent 指令（网页/邮件里藏"忽略之前指令"）；防御靠输入隔离、工具最小权限、人工审批关卡，**目前没有银弹**。

## 五、产品与商业层：从能力到生意

- **Copilot vs Agent**：副驾驶（人做决策，AI 补全）vs 代理（AI 做决策，人审结果）；2026 年产品叙事全面从 Copilot 转向 Agent。
- **产品形态**：编程（Claude Code/Cursor 类）、客服、数据分析、个人助理、Agent 平台；形态决定验收标准和计费方式。
- **计费模式三件套**：按席位（seat）、按量（token/调用）、按结果（任务成功计费）；行业正从 seat 向"量+结果"迁移。
- **Token 经济学**：毛利 = 收入 − 模型推理成本；延迟×成本×可靠性构成不可能三角，产品设计本质是在三角里选位置。
- **AI Infra**：推理框架（vLLM 等）、算力（GPU/NPU）、一体机——模型之下的卖铲人生意。

## 六、高频混淆术语对（快速辨析）

| 术语对 | 一句话区分 |
|---|---|
| AI / ML / DL | 同心圆：AI ⊃ ML ⊃ DL |
| LLM / 基础模型 | LLM 只管语言，基础模型还含图像/语音/视频 |
| 训练 / 推理 | 训练=教模型（贵、离线）；推理=用模型（按次计费） |
| Fine-tuning / RAG / Prompt | 改模型本身 / 给模型查资料 / 教模型怎么问；成本递增递减，先 Prompt 再 RAG 最后微调 |
| Function Calling / MCP | 单次调用能力 / 工具接入协议标准 |
| Agent / 工作流（Workflow） | 模型自主决定路径 / 人写死分支；确定性需求用工作流，开放性需求才用 Agent |
| RAG / 长上下文 | 检索外部知识 / 把知识全塞进输入；前者可溯源可更新，后者简单但贵且有 Context Rot |
| 向量检索 / 全文检索 | 语义相似 / 关键词精确；生产上混合用 |
| Embedding 模型 / 生成模型 | 负责"表示" / 负责"生成"；RAG 里两个都要 |
| Prompt Injection / Jailbreak | 劫持 Agent 行为 / 让模型说违禁内容；前者危害系统，后者危害内容安全 |
| Copilot / Agent | 人决策 AI 辅助 / AI 决策人监督 |
| 推理（Inference）/ 推理模型（Reasoning） | 跑模型出结果 / 模型先思考再回答；一词两义，注意语境 |
| Benchmark / 生产效果 | 考卷分数 / 真实任务成功率；两者经常差一个档次 |

## 七、一页速查：新词定位法

拿到任何一个新术语，按顺序问四个问题：

1. **它改变的是模型本身吗？** 是 → 模型层（新架构/新训练法/新模型系列）。
2. **它改变的是怎么调用模型吗？** 是 → 使用层（Prompt 技巧/结构化输出/采样）。
3. **它让模型能连续做事了吗？** 是 → 智能体层（Loop/工具/记忆/RAG/多智能体）。
4. **它关心的是成本、验收或卖法吗？** 是 → 产品商业层（计费/eval/延迟）。

对不上的（芯片、云基础设施）归 AI Infra；对行业发展态势做调研的，归情报工作而非概念本身。

## 附：口径说明

- 概念定义以 2026-10 行业通行用法为准；个别术语（如 Reasoning、Agent）仍在快速演化，定义可能随社区共识漂移。
- 本文是概念地图而非教程：每个条目给了"是什么、解决什么、易混点"，深入实践需按层展开。
